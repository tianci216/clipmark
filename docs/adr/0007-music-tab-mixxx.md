# Music tab: a read-only Mixxx library view ported from mobile-mixxx

mobile-mixxx was a separate Flask app (port 8080) that browsed the Mixxx DJ library and played tracks on the phone. We folded it into ClipMark as a second top-level tab — **Clips | Music** — so one server, one app and one Tailscale address cover both. Everything it did is kept: All Tracks / crates / playlists, the Lucene-style search, sortable columns (a playlist opens in its own order), the phone card list with a slide-in drawer and sort dropdown, and a player bar with buffered/played progress, seek, previous / play-pause / next, auto-advance and "click the playing track to restart".

Server (`server/src/music.ts`, `server/src/musicQuery.ts`): `GET /api/music/crates`, `/playlists`, `/tracks?crate=&playlist=&q=&sort=&order=`, `/audio/:id` (Range-aware, MIME from Mixxx's `filetype`). The Mixxx database is opened **read-only, per request** with better-sqlite3 and never written. Audio is served only from files under the **Music Folder**; anything else is 403. The search parser is a port of the luqum grammar mobile-mixxx used — same tokens, precedence and operation flattening — and was checked query-for-query against the Python original, so a query produces the same SQL. A query that does not parse is searched as plain text (as before); one that parses but cannot become SQL (`bpm:fast`) is a 400, which the client shows under the search box while keeping the list (mobile-mixxx answered 500).

The default database lives in Mixxx's sandbox container, so the first open from ClipMark triggers macOS's "ClipMark would like to access data from other apps" prompt (`kTCCServiceSystemPolicyAppData`, attributed to the .app). The open blocks until the prompt is answered; because better-sqlite3 opens synchronously, each request first does an async `fs.promises.open` so the wait parks a libuv worker and the rest of the app stays responsive. An ad-hoc re-signed build may be asked again.

Settings: `mixxxDbPath` and `musicBase` live in the `settings` table (ADR-0005 style: server-owned, applied on the next request). Resolution is saved setting → the `MIXXX_DB_PATH` / `MUSIC_BASE` env vars mobile-mixxx read → defaults (`~/Library/Containers/org.mixxx.mixxx/.../mixxxdb.sqlite`, `~/Documents/Music`). `PUT /api/settings` validates both (the database must open and have a `library` table) and reports `trackCount`.

Client: the tab, the Music library state and a single `Audio` element live in `App`, so music keeps playing when you switch to Clips; the player bar stays docked there while a track is loaded. Next / previous follow the list on screen while it holds the playing track, else the list it was picked from.

Rejected: keeping mobile-mixxx as its own process behind a proxy (two servers, two runtimes), and launchd socket activation (the ClipMark shell already owns the server's lifecycle).
